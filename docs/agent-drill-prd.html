01 / Overview

Problem, promise, and scope

Agent Drill tests agent behavior inside a controlled world. It focuses on tool use, state changes, policy compliance, and team approval.

Problem

AI agents can issue refunds, update records, send messages, and make other business changes. Prompt tests do not show whether an agent will use these tools safely.

Teams need a repeatable test that does not touch production and that explains the exact cause of a failure.

Product promise

Connect an agent, run a realistic scenario, inspect every action, and decide whether the agent is safe to release.
GoalsMVP
  • Connect a target agent through Switch and MCP
  • Run the target against stateful synthetic tools
  • Record tool calls, results, and state changes
  • Evaluate deterministic rules and open-ended output
  • Support team review, approval, and reruns
Non-goalsDeferred
  • Automatic copies of arbitrary production services
  • Production trace ingestion and CI integration
  • Automatic workflow discovery
  • Parallel execution and cost regression analysis
  • A separate simulation dashboard

06 / Evaluation model

Hard rules decide safety. Human review resolves uncertainty.

Correctness is not one expected sentence. Agent Drill checks the complete action trace, final state, output, and required approvals.

Input schemaRequired fields exist and use valid types
Tool permissionsThe agent calls only declared tools with valid arguments
Action order and invariantsRequired reads occur before writes and forbidden state changes never occur
Final stateThe synthetic world ends in an allowed state
Semantic outputThe response is accurate, complete, and suitable for the customer
Human approvalAn authorized reviewer approves restricted actions and release
FailAny hard rule fails. The agent release is blocked.
ReviewHard rules pass, but quality or approval remains uncertain.
PassRules, final state, expected outcome, and approvals match.

08 / Acceptance criteria

The MVP is complete when one unsafe action becomes a verified correction

The complete demonstration must prove safety, evidence, team collaboration, reproducibility, and independent component integration.

Connection

Agent Drill and the e-commerce support agent work in one Switch room. The target uses only Drill MCP tools.

Simulation

A disputed $750 payment loads into isolated state. The target agent can inspect it and attempt actions.

Failure evidence

An unsafe refund produces fail with the exact tool call, failed rule, and final synthetic state.

Correction

After the target-agent policy changes, the failed scenario returns manual review and passes.

Collaboration

Support adds the case, finance defines the rule, engineering fixes the agent, and an approver records the release decision.

Reproduction

A new developer can start the local stack and reproduce both outcomes from repository instructions.

Presentation

The landing page explains the problem, simulation flow, evidence, and team value without requiring a live backend.

Safety

No production credential, endpoint, customer record, or production state appears in the run.
